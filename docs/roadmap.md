# 路线图

路线图按当前实现状态维护；早期设计文档仍保留作为历史记录，不覆盖当前 v0.2 协议。

## 阶段 0：仓库与协议（已完成）

- [x] 初始化 Python 包和 UV 工作流
- [x] 固定 v0.2 输入输出维度
- [x] 建立 JSONL 数据协议和校验器
- [x] 建立模型、状态和时间步长的数据类型
- [x] 维护可复现的锁定依赖

## 阶段 1：可运行基线（已完成）

- [x] 实现 32 维输入编码器和 CfC-512 动力核心
- [x] 实现 8 维情绪和 6 维行为输出
- [x] 支持单步、序列和隐状态传递
- [x] 支持 CPU/CUDA 推理和 checkpoint 保存/加载
- [x] 区分当前刺激与历史条件
- [x] 支持非负时间间隔和无刺激状态更新
- [x] 提供基础模型、数据和状态测试

## 阶段 2：训练与评估（部分完成）

- [x] 支持 `zeros`、`provided`、`fixed` 历史输入模式
- [x] 建立合成老师数据和 held-out 基准
- [x] 报告情绪/行为 MAE、MSE、基线 skill 和方向命中率
- [x] 检查脉冲恢复和不同前史的状态差异
- [ ] 完成系统的参数规模、训练成本和推理性能测量
- [ ] 设计更多未见场景和跨角色泛化实验
- [ ] 比较 CfC、GRU 和其他递归基线
- [ ] 建立人工确认的高质量评估集

- [ ] 建立模型版本注册、回滚和兼容性检查流程

## 研究原则

每次算法升级都保留旧模型、协议版本、固定测试序列和基准结果。先确认可重复、可解释的改进，再扩大模型和集成范围。
