# 核心架构与运行边界

本文档描述当前实现的模块关系、状态流转和外部集成边界。模型细节见 [核心模型技术方案](core-model-technical-plan.md)，公开调用见 [Python 推理接口](python-api.md)。

## 项目定位

NeuroBrain 是一个独立、可训练、持续运行的人工状态动力系统。它学习外部刺激、内部隐状态与情绪/行为输出之间的动态关系，为角色和 Agent 提供可持续演化的数值状态。

它不模拟真实生物大脑，不直接读取文本，不生成最终台词，也不执行 Live2D、语音或其他外部动作。

## 核心运行架构

```text
文本/事件
   ↓
宿主应用或 LLM：提取结构化当前刺激
   ↓
NeuroBrainSession 或 NeuroBrainModel
   ├─ 输入编码器（16 → 32）
   ├─ CfC 动力核心（512 维隐状态）
   └─ 情绪/行为解码器（8 + 6）
   ↓
情绪状态 + 行为倾向
   ↓
宿主应用：回复、决策、动作或记录
```

## 输入编码层

底层模型有两个语义独立的 8 维通道：

1. **当前刺激 `current_stimulus`**：本次事件新增的外部影响。
2. **历史条件 `historical_condition`**：当前情境携带的背景条件。

两者都使用固定的八维情绪顺序：

```text
joy, trust, fear, surprise,
sadness, disgust, anger, anticipation
```

每个值必须在 `[0, 1]`。历史条件不能覆盖 CfC 隐状态，也不能自动变成新的刺激事件。

### 公开 facade 和底层模型的差异

`NeuroBrainSession` 面向业务集成：每次只接收一个当前刺激，把 `historical_condition` 固定为全零，并在 session 内保存 CfC 隐状态。这样外部调用只需要维护 `session_id`。

`NeuroBrainModel` 面向训练和实验：调用方可以逐步或批量传入历史条件、每步时间间隔和初始隐状态。

因此，当前公开 facade 的业务输入是 8 维；底层 v0.2 张量协议仍是 16 维输入通道加时间间隔。

## CfC 动力核心

核心维护 512 维连续隐状态，每次更新综合当前隐状态、编码后的输入和 `delta_seconds`：

```text
h(t + Δt) = CfC(h(t), Encode(current, history), Δt)
```

当前模型使用单层 `ncps.torch.CfC`、32 维输入编码和 `batch_first=True`。支持：

- 单步更新和整段序列前向；
- 隐状态从一个时间步传到下一个时间步；
- 非负时间间隔，包括 `delta_seconds=0`；
- CPU 和 CUDA 运行；
- 保存/加载带模型配置和协议版本的 checkpoint。

## 输出解码层

共享 CfC 隐状态通过两个独立线性层解码：

- 情绪状态：8 维，逐维 sigmoid，值在 `[0, 1]`；
- 行为倾向：6 维，逐维 sigmoid，值在 `[0, 1]`。

情绪不使用 Softmax，不要求各维之和为 1。行为倾向不是动作指令，外部系统需要自行决定如何使用它。

## 状态生命周期

```text
加载 checkpoint
   ↓
创建一个角色/会话对应的 session
   ↓
update(stimulus) × N
   ├─ 读取最新状态：read()
   ├─ 读取单维：read("joy")
   └─ 重新开始：reset()
```

一个 session 只能表示一个独立的连续状态流。不同角色、用户或对话必须使用不同 session。当前隐状态只保存在进程内；进程重启后没有公开的自动恢复机制。

## 长期记忆边界

NeuroBrain 的隐状态用于短期连续性和过去刺激的动态影响，不是可检索的文本记忆。具体历史经历、长期故事、摘要和向量检索由外部 Memory 系统负责。

需要区分：

1. 历史事件发生时的状态；
2. 当前回忆该事件产生的新刺激；
3. NeuroBrain 对当前事件计算出的状态。

第一版公开 facade 不接入真实 Memory，仅使用全零历史条件和连续 CfC 隐状态。

## 外部集成边界

LLM 或规则层负责：

- 理解文本和事件；
- 生成 8 维结构化刺激；
- 读取 NeuroBrain 输出并组织回复或决策。

NeuroBrain 负责：

- 校验刺激输入；
- 更新连续隐状态；
- 输出可记录、可传输的情绪和行为数值。

外部执行系统负责将决策转换为语音、Live2D、工具调用或 Agent 操作。仓库提供可选的
JSON WebSocket 状态服务，但不负责这些执行动作；宿主仍负责启动服务、鉴权和进程生命周期。

## 训练和运行边界

训练脚本使用 JSONL 序列、变长 batch 和有效时间步掩码。默认 `history_mode=zeros` 与公开 facade 对齐；`provided` 和 `fixed` 是底层历史通道实验模式。

在线推理只更新隐状态，不更新模型权重。模型训练、评估、checkpoint 发布和线上加载应分成独立流程，以便回滚和比较结果。

## 研究原则

每次模型或协议升级都应保留：

- 旧 checkpoint 和协议版本；
- 固定测试序列与合成基准结果；
- 训练参数、数据版本和随机种子；
- 对外 API 的兼容性说明。

输出数值应结合独立测试和人工复核解释，不能单独作为真实心理或动作正确性的证明。
